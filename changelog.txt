*** Dat Theme Changelog ***

= 1.9.6 - 2026/09/30 =
* This release gives the custom-overlay submenu toggle a comfortable tap target
* Tweak - The arrow-mode toggle button inside a custom overlay gets a 44px minimum hit area (Apple HIG; WCAG floor is 24px) with the caret centered - the bare svg was a 12px target

= 1.9.5 - 2026/09/30 =
* This release adds collapsible submenus inside the Navigation block custom overlay - parents collapsed by default, tap the caret to expand, as large menus need on mobile
* New - theme-scripts toggles the theme own dat-sub-open class on the parent item; the listener is scoped to toggles inside an open custom overlay only and never reads or writes WordPress state, so it cannot touch desktop menus, the default overlay, or third-party menus
* New - Overlay submenus are collapsed by default and expand under dat-sub-open; label and caret share a row, the submenu wraps below the parent full-width; the caret shows again, points down when closed (core rotates it on aria-expanded, which WordPress pins true in overlays, so the closed state is explicitly zeroed) and up when open
* Dev note - When Gutenberg #82596 (custom-overlay toggles become functional) reaches a WordPress release, remove the listener and re-key the overlay CSS on aria-expanded

= 1.9.4 - 2026/09/30 =
* This release completes the custom-overlay layout: submenus flow BELOW their parent
* Fix - Navigation items inside a custom overlay stack vertically (core lays nav-item children in a row, so a static submenu sat BESIDE its parent); alignment follows the block's own justification setting
* Fix - Submenus inside a custom overlay are always expanded and the submenu toggle icons hidden, mirroring core: WordPress pins overlay submenus open and the toggles are inert there. The 1.9.3 collapse-on-toggle rules keyed a collapse that cannot occur and are removed

= 1.9.3 - 2026/09/30 =
* This release completes 1.9.2's custom-overlay support and fixes asset cache busting on child-theme sites
* Fix - The menu list now shows inside the Navigation block's custom overlay: the theme's mobile rules hide every navigation container and only core's default-overlay styles out-specified that, so a custom overlay opened empty (every custom-overlay site was carrying its own child-theme patch for this)
* Fix - DAT_VERSION now reads the parent theme's version. It previously read the ACTIVE theme, so on every child-theme site all parent assets were served as ?ver=<child version> — a URL that never changes across theme updates while the files ship with a one-year immutable cache lifetime, leaving returning visitors on stale CSS/JS after every update. The active theme's own style.css keeps its own version, so a child stylesheet still cache-busts on a child version bump

= 1.9.2 - 2026/09/30 =
* This release fixes broken submenus in the Navigation block's mobile overlay and on desktop
* Fix - Removed the legacy submenu-toggle click handler from theme-scripts. It manually flipped inline display styles on submenu containers, fighting the Navigation block's own Interactivity API toggles: the first tap hid the submenu core had just opened, and clicking a desktop submenu arrow left an inline display:none that kept that dropdown hidden until reload. The block handles submenu toggling natively.
* Fix - Removed the mobile display:none on submenu containers in the site-header-3 drawer that only the deleted handler could undo; drawer submenus now show expanded, WordPress's native overlay behaviour
* New - Structural support for the Navigation block's custom overlay (overlay template part): submenus flow in place, collapsed until the block's own toggle opens them, with the toggle arrow rotating on open. Menu colors and typography stay on the blocks
* Tweak - theme-scripts is now enqueued with the theme version for correct cache busting when the theme updates
